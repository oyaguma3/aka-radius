# D-06 エラーハンドリング詳細設計書 (r21)

## 1. 概要

### 1.1 目的

本書は、aka-radius の各サブコマンド（auth・acct・admin）と運用のコマンドで、異常をどう見つけ、どう応え、どう戻るかを定義する。正はコード（`cmd/`・`internal/`）と管理API の OpenAPI（`docs/openapi/admin-api.yaml`）である。決定事項は設計概要（`docs/design-overview.md`）、運用の手順は運用ガイド（`docs/operation-guide.md`）にある。

### 1.2 対象

| 対象 | 役目 | 主な異常 |
|---|---|---|
| auth（`aka-radius auth`） | RADIUS 認証、EAP-AKA / EAP-AKA' の状態機械、認証ベクターの取得 | 不正なパケット、加入者・刻印・ルールによる拒否、取得先の拒否と障害、Valkey の障害 |
| acct（`aka-radius acct`） | RADIUS Accounting、利用の集計 | 不正なパケット、重複と順序の誤り、Valkey の障害 |
| admin（`aka-radius admin`） | 管理API（mTLS）、監査ログ | 登録していないクライアント証明書、入力の誤り、状態の誤り、Valkey の障害 |
| コマンド（`client`・`sources check`・`admin-cert`・`fingerprint`・`healthcheck`） | 運用者が動いているコンテナの中で使う | 引数の誤り、対象の有無、ファイルの誤り |

Valkey・Fluent Bit・compose・公開範囲は D-08 で定義する。

### 1.3 扱わないもの

| 機能 | 受けたときの扱い |
|---|---|
| 仮名と高速再認証 | 永続 ID を求めてフル認証に誘導する（§4.2） |
| EAP-Notification | 使わない |
| EAP-AKA と EAP-AKA' の切り替え（NAK） | 扱わない。方式は Identity の先頭の文字で決める（設計概要 §7.1） |
| 取得先への再試行 | しない。取得先ごとの遮断器に任せる（§8.3） |

## 2. 誤りの分類と重大度

### 2.1 分類

| 分類 | 説明 | 例 |
|---|---|---|
| 通信（COMM） | 外のものとの接続・通信の障害 | Valkey に届かない、取得先のタイムアウト・5xx |
| プロトコル（PROTO） | RADIUS・EAP・HTTP の形の誤り | Message-Authenticator の不一致、未知の EAP の Subtype、JSON の誤り |
| 判定（AUTHZ） | 加入者・刻印・ルールによる拒否 | 未登録、`inactive`、刻印がない、一致するルールがない |
| 認証（AUTH） | EAP-AKA の検証の失敗 | AT_MAC の不一致、RES の不一致、再同期の上限 |
| データ（DATA） | データの不整合・不在 | 本PoC の形の加入者、セッションがない、Accounting の順序の誤り |
| 設定（CONF） | 起動・読み直しのときの設定やファイルの誤り | 取得先の登録簿の形の誤り、ピンのファイルがない |
| システム（SYS） | 内部の思わぬ障害 | パニック、待ち受けの失敗 |

### 2.2 重大度

| 重大度 | 定義 | ログのレベル | 対応 |
|---|---|---|---|
| Critical | サービスを続けられない | ERROR（プロセスを終える） | compose の `restart` で起動し直す。原因を直す |
| Error | 個々の要求の失敗で、運用者が見るべきもの | ERROR | 拒否または応答しない。監視で拾う |
| Warning | 個々の要求の正当な拒否、潜在的な問題 | WARN | 拒否する。数が増えたら調べる |
| Info | 正常の範囲で記録するもの | INFO | 記録だけ |

## 3. 共通の扱い

### 3.1 RADIUS の受け口（auth・acct）

auth と acct は同じ受け口（`internal/radiussrv`）を使う。

| 状況 | 扱い | ログ |
|---|---|---|
| 送信元の共有シークレットがない（`client:{ip}` がなく、予備の共有シークレットも空） | 捨てる（応答しない） | `RADIUS_NO_SECRET`（WARN） |
| 共有シークレットを Valkey から引けない | 予備の共有シークレットがあればそれで続け、なければ捨てる | `RADIUS_SECRET_ERR`（WARN） |
| 送信元の IP を取り出せない | 同上 | `RADIUS_IP_EXTRACT_ERR`（WARN） |
| パケットの形が壊れている | ライブラリが捨てる | `RADIUS_LIB_ERR`（WARN。共有シークレットが決まらずに捨てたときは DEBUG） |
| 処理中のパニック | 回復して処理を続け、そのパケットには応答しない（NAS は送り直す） | `SYS_PANIC`（ERROR） |
| 同時に処理する上限（`RADIUS_MAX_INFLIGHT`、既定 256）を超えた | 応えずに捨てる（まだ何もしていないので、NAS の再送を待っても害がない） | `RADIUS_OVERLOAD`（WARN。1 秒に 1 回に間引く） |
| 要求の期限（`RADIUS_REQUEST_TIMEOUT`、既定 4 秒）を過ぎた | auth は拒否で終える。acct は記録できずに応答しない | 期限で失敗した操作の event_id |
| 同じ要求の再送 | 前に送った応答を送り直す。処理中なら捨てる | `AUTH_`・`ACCT_DUPLICATE_REPLAYED`（INFO）、`…_DUPLICATE_DROPPED`（DEBUG） |
| 応答を送れない | — | `PKT_SEND_ERR`（ERROR） |

- ライブラリ（`layeh.com/radius`）によるパケットの検証は使わず、ハンドラーで Message-Authenticator・Request Authenticator を確かめる。ライブラリに任せると、送信元のない素のテキストのログだけで捨てられるため。
- 受けたパケットはすぐに goroutine に渡す（ライブラリが同じ送信元と Identifier の要求をハンドラーが戻るまで黙って捨てるのを効かなくし、重複は重複応答のキャッシュだけで扱う。段階 2-6 の M11）。
- 応答しなかった要求（捨てた、パニック、acct の記録の失敗）は、重複応答のキャッシュに印を残さない。次の再送は新しい要求として処理する。

### 3.2 起動のときの誤り

どれも、ログを出して終了コード 1 で終える。compose の `restart` で起動し直す（運用ガイドの 2 章）。

| event_id | サブコマンド | 原因 |
|---|---|---|
| （`error` だけ） | すべて | 環境変数の値の形が違う、必須の値（`RADIUS_VALKEY_PASSWORD`）がない |
| `VALKEY_CONN_ERR` | auth・acct | Valkey に届かない、パスワードが違う |
| （`failed to connect to Valkey`） | admin | 同上（admin のこのログには event_id がない） |
| `SOURCES_LOAD_ERR` | auth・admin | 取得先の登録簿が読めない、形が違う。auth では証明書と鍵の組が合わない |
| `ADMIN_CLIENTS_LOAD_ERR` | admin | 管理クライアントのピンのファイルがない・読めない・形が違う・1 つもない |
| `SERVER_CERT_LOAD_ERR` | admin | 管理API のサーバー証明書か鍵が読めない、組が合わない |
| `AUDIT_DIR_ERR` | admin | 監査ログのディレクトリに書けない |
| `SYS_LISTEN_ERR` | すべて | 待ち受け（RADIUS・管理API・healthcheck の口）を開けない、またはシグナルの前にサーバーが終わった |

- 取得先が 1 つもない登録簿は誤りにしない（auth は起動し、WARN を出してすべての認証を拒否する）。

### 3.3 読み直し（SIGHUP）の誤り

auth は取得先の登録簿を、admin はピン・サーバー証明書・取得先の登録簿を、`SIGHUP` で読み直す。それぞれ独立に扱い、**失敗したら前のまま続ける**。

| event_id | サブコマンド | 原因 |
|---|---|---|
| `SOURCES_RELOAD_ERR` | auth・admin | 登録簿が読めない・形が違う。auth では、加入者が指している取得先（取得先ごとの加入者の数が 0 でない）を消す登録簿も断る |
| `ADMIN_CLIENTS_RELOAD_ERR` | admin | ピンのファイルが読めない・形が違う・1 つもない |
| `SERVER_CERT_RELOAD_ERR` | admin | サーバー証明書か鍵が読めない、組が合わない |

成功したときは `SOURCES_RELOADED`・`ADMIN_CLIENTS_RELOADED`・`SERVER_CERT_RELOADED`（INFO）を出す。

### 3.4 Valkey が止まったとき

| サブコマンド | 動き |
|---|---|
| auth | 予備の共有シークレットが空（推奨）なら、共有シークレットを引けずにパケットを捨てる。NAS が送り直し、Valkey が戻った後に続く。予備の共有シークレットで受けたときは、加入者や EAP の会話を読めずに拒否する |
| acct | 予備の共有シークレットが空なら同じく捨てる。受けたときも、記録できなければ応答しない（D-10 §5.10）。どちらも NAS の再送で記録される |
| admin | 管理API は 500（`SYSTEM_FAILURE`）。起動のときに届かなければ起動しない（§3.2） |
| 各コンテナの healthcheck | Valkey の PING が失敗するので unhealthy になる（`HEALTH_VALKEY_ERR`） |

- Valkey への再接続は go-redis の接続プールに任せる。戻ったことを知らせるログは出さない。Valkey の誤りのログが止まったことで判断する。

## 4. auth

EAP の状態機械と取得先のクライアントの作りは D-09。ここでは異常のときの扱いを書く。拒否はどれも EAP-Failure の Access-Reject で応える（応えずに再送を待つことはしない）。

### 4.1 RADIUS の層

| 状況 | 応答 | ログ |
|---|---|---|
| Message-Authenticator がない・合わない | なし | `PKT_MA_INVALID`（WARN） |
| EAP-Message がない | なし | `PKT_NO_EAP`（WARN） |
| Access-Request・Status-Server 以外の Code | なし | `PKT_UNKNOWN_CODE`（WARN） |
| Status-Server の Message-Authenticator が合わない | なし | `RADIUS_STATUS_AUTH_FAIL`（WARN） |

### 4.2 EAP の層

| 状況 | 応答 | ログ |
|---|---|---|
| EAP のパケットを解析できない | Access-Reject | `EAP_PARSE_ERR`（WARN） |
| 最初の要求が Identity でない（AKA の Subtype が Identity 以外） | なし | `EAP_NOT_IDENTITY`（WARN）、`PKT_DROP`（INFO） |
| Identity の形が違う（IMSI が 15 桁でないなど） | Access-Reject | `EAP_IDENTITY_INVALID`（WARN） |
| Identity の先頭の文字が対応しない方式（EAP-SIM など） | Access-Reject | `EAP_UNSUPPORTED_TYPE`（WARN） |
| RADIUS の User-Name と EAP の Identity が違う | 続ける（判定には EAP の Identity を使う） | `EAP_IDENTITY_MISMATCH`（INFO） |
| 仮名・高速再認証の ID | AKA-Identity で永続 ID を求める（フル認証に誘導） | — |
| 永続 ID を求めた後の応答に使える ID がない | Access-Reject | `EAP_IDENTITY_INVALID`（WARN） |
| 想定しない時点の Identity の応答 | Access-Reject | `EAP_UNEXPECTED_IDENTITY`（WARN） |
| 未知の Subtype | Access-Reject | `EAP_UNKNOWN_SUBTYPE`（WARN） |
| 端末の Authentication-Reject・Client-Error | Access-Reject | `EAP_AUTH_REJECT`・`EAP_CLIENT_ERROR`（WARN） |
| State の会話（`eap:`）がない（期限 60 秒切れなど） | Access-Reject | `EAP_CTX_NOT_FOUND`（WARN） |
| 会話を作れない・更新できない・読めない・壊れている | Access-Reject | `EAP_CTX_CREATE_ERR`・`EAP_CTX_UPDATE_ERR`・`EAP_CTX_DECODE_ERR`・`EAP_CTX_INVALID`（ERROR） |
| 状態機械の遷移の誤り | Access-Reject | `EAP_STATE_ERR`（ERROR） |
| EAP のパケットを組み立てられない | Access-Reject | `EAP_BUILD_ERR`（ERROR） |

### 4.3 ベクターを取る前の判定

最初の要求（IMSI が分かった時点）で、取得先を呼ぶ前に次の順に確かめる（設計概要 §8.1。決定事項 4）。どれかに当たれば取得先を呼ばずに拒否するので、拒否する IMSI では取得先の SQN が進まない。

| 順 | 状況 | ログ |
|---|---|---|
| 1 | 加入者がいない | `AUTH_SUBSCRIBER_NOT_FOUND`（WARN） |
| 1 | 加入者が本PoC の形（`state` がない）で読めない | `AUTH_SUBSCRIBER_INVALID`（ERROR） |
| 1 | 加入者を Valkey から読めない | `AUTH_SUBSCRIBER_LOOKUP_ERR`（ERROR） |
| 2 | 状態が `inactive`・`terminated` | `AUTH_SUBSCRIBER_INACTIVE`・`AUTH_SUBSCRIBER_TERMINATED`（WARN） |
| 3 | 刻印がない（信頼しない送信元の刻印は、ないものとして扱う。`AUTH_STAMP_UNTRUSTED`、DEBUG） | `AUTH_STAMP_MISSING`（WARN） |
| 3 | 刻印が 2 つ以上、10 進の 1 以上の数でない | `AUTH_STAMP_MULTIPLE`・`AUTH_STAMP_INVALID`（WARN） |
| 3 | 刻印の信頼の印（`client:{ip}` の `trust_stamp`）を読めない | `AUTH_STAMP_LOOKUP_ERR`（ERROR） |
| 4 | テナント・NAS-Identifier・SSID がすべて一致するルールがない | `AUTH_POLICY_DENIED`（WARN） |

Access-Accept の前に状態だけもう一度読み、`active` でなくなっていれば同じ event_id で拒否する。

### 4.4 取得先の誤り

取得先のクライアント（`internal/auth/source`）は、結果を契約 §9.3 に従って分類する。どの分類でも、その認証は拒否する。

| 分類 | 状況 | 遮断器に数える | ログ |
|---|---|---|---|
| 拒否 | 403（加入者がいない・許可がない・止めてあるなど）、400・501（設定の食い違い。許していない `anId` など）。ProblemDetails の `cause` つき | 数えない（成功として扱う） | `VECTOR_REJECTED`（403 は WARN、400・501 は ERROR） |
| 一時的な誤り | 500・503、接続や TLS の失敗、タイムアウト | 数える | `VECTOR_TEMPORARY_ERR`（ERROR） |
| 契約違反 | 形の合わない 200（要素の数・`avType`・値の長さ）、本文のない 4xx・501、契約にないステータス、大きすぎる応答 | 数える | `VECTOR_CONTRACT_VIOLATION`（ERROR） |
| 遮断器が開いている | 要求を送らない | — | `VECTOR_CIRCUIT_OPEN`（ERROR） |
| 取得先が決まらない | 加入者の `source_id` が登録簿にない（取得先が 1 つもない登録簿を含む） | — | `VECTOR_SOURCE_UNKNOWN`（WARN） |
| 取得先を読めない | 加入者の取得先を Valkey から読めない | — | `VECTOR_SOURCE_LOOKUP_ERR`（ERROR） |
| 不明 | 上のどれでもない | — | `VECTOR_UNKNOWN_ERR`（ERROR） |

- ログには `source_id`・`http_status`・`cause`・`reason`・`latency_ms` を付ける（値・鍵は入れない）。
- 再同期のときの取得の誤りも同じ扱い。
- 遮断器の状態は auth が `stat:sources` に、状態が変わったときと 30 秒ごとに書く。書けなくても認証は続け、書けない間は最初の 1 回だけ `SOURCES_STATUS_WRITE_ERR`（WARN）を出す。

### 4.5 Challenge の検証と Access-Accept

| 状況 | 応答 | ログ |
|---|---|---|
| AT_MAC が合わない | Access-Reject | `AUTH_MAC_INVALID`（WARN） |
| AT_RES が合わない | Access-Reject | `AUTH_RES_MISMATCH`（WARN） |
| そのほかの検証の失敗 | Access-Reject | `AUTH_VERIFY_FAIL`（WARN） |
| 2 回目の Synchronization-Failure（再同期は 1 回の会話で 1 回まで） | Access-Reject | `AUTH_RESYNC_LIMIT`（WARN） |
| セッションを作れない | Access-Reject | `SESSION_CREATE_ERR`（ERROR） |
| 利用の集計に `auth_ok` を足せない | Access-Accept を返す（集計の 1 件の欠けより、認証を通すことを優先する） | `USAGE_WRITE_ERR`（ERROR） |

## 5. acct

詳しくは D-10 §5・§7。要点:

| 状況 | 応答 | ログ |
|---|---|---|
| Request Authenticator が合わない、Status-Server の Message-Authenticator が合わない | なし | `RADIUS_AUTH_ERR`（WARN） |
| Acct-Status-Type がない、Start・Stop・Interim で Acct-Session-Id がない | なし | `RADIUS_PARSE_ERR`（WARN） |
| Accounting-Request・Status-Server 以外の Code、未知の Acct-Status-Type | なし | `RADIUS_UNKNOWN_CODE`（WARN） |
| 記録できない（Valkey、要求の期限） | **なし**（NAS に送り直させ、利用の集計の取りこぼしを防ぐ） | `VALKEY_CONN_ERR`（ERROR） |
| Start・Interim の重複 | Accounting-Response（集計しない） | `ACCT_DUPLICATE_START`・`ACCT_DUPLICATE_INTERIM`（WARN） |
| Stop の後の Stop | Accounting-Response（何もしない） | `ACCT_DUPLICATE_STOP`（DEBUG） |
| 順序の誤り（`start_after_stop`・`no_start_received`・`interim_after_stop`） | Accounting-Response（数える） | `ACCT_SEQUENCE_ERR`（WARN） |
| Class がない、セッションがない | Accounting-Response（集計だけ） | `ACCT_SESSION_NOT_FOUND`（WARN） |
| テナントが分からない | Accounting-Response（テナント `0` で集計） | `ACCT_TENANT_UNKNOWN`（WARN） |
| IMSI が分からない | Accounting-Response（集計しない） | `ACCT_IMSI_UNKNOWN`（WARN） |
| 刻印が 2 つ以上・数でない・信頼の印を読めない | Accounting-Response（刻印を使わない） | `ACCT_STAMP_MULTIPLE`・`ACCT_STAMP_INVALID`（WARN）、`ACCT_STAMP_LOOKUP_ERR`（ERROR） |
| 7 日より前の日、未来の Event-Timestamp | Accounting-Response（足し込まない・受け取った時刻を使う） | `ACCT_USAGE_TOO_OLD`・`ACCT_EVENT_TIMESTAMP_FUTURE`（WARN） |
| 累計が減った | Accounting-Response（今回の累計を増分にする） | `USAGE_COUNTER_RESET`（WARN） |
| セッションの索引の掃除に失敗した | — （次の 1 時間後にまた試す） | `SESSION_SWEEP_ERR`（ERROR） |

- 本PoC の acct は Valkey に書けなくても応答していた（停止中の課金データは失われた）。MVP では応答しない（設計概要 §17.1 の「段階 2-4 で決めたこと」）。

## 6. admin（管理API）

### 6.1 接続

| 状況 | 扱い | ログ |
|---|---|---|
| クライアント証明書がない | TLS のハンドシェイクで断る | `ADMIN_CLIENT_REJECTED`（WARN。`reason` `no client certificate`、`src_ip`） |
| ピンのファイルにないフィンガープリント | 同上 | `ADMIN_CLIENT_REJECTED`（`reason` `not configured`、`fingerprint`） |
| 期限の外の証明書 | 同上 | `ADMIN_CLIENT_REJECTED`（`reason` `outside validity period`） |
| そのほかの TLS の失敗 | 接続を閉じる | DEBUG（HTTP サーバーのエラーのログ） |

- 断ったログの `fingerprint` を、ピンのファイルに書いた値と比べて登録の誤りを確かめる（運用ガイドの 5.1）。

### 6.2 誤りの応答（ProblemDetails）

誤りは `application/problem+json` で、`title`・`status`・`cause`（必須）・`detail`・`invalidParams`（`param`・`reason`）を返す。`cause` の名前は本PoC の Provisioning API の名前を残し、MVP で足した誤りは aka-vecgen と同じ名前にした（設計概要 §11.1。段階 2-3 の G11）。

| HTTP | `cause` | 状況 |
|---|---|---|
| 400 | `INVALID_MSG_FORMAT` | 本文が JSON でない、オブジェクトでない、知らない項目がある、256 KiB を超える |
| 400 | `INVALID_QUERY_PARAM` | クエリーの値の形が違う（`limit`・`cursor`・`date`・`tenantId`・`imsi` など） |
| 400 | `MANDATORY_IE_MISSING` | 必須の項目がない（PATCH で項目が 1 つもないときも） |
| 400 | `MANDATORY_IE_INCORRECT` | 必須の項目の値が違う（IMSI、`state`、ルールの項目の範囲など） |
| 400 | `OPTIONAL_IE_INCORRECT` | 任意の項目の値が違う。`X-Operator-Id` の形が違う |
| 400 | `UNKNOWN_SOURCE` | `sourceId` が取得先の登録簿にない |
| 404 | `USER_NOT_FOUND` | 加入者がいない（IMSI の形が違うときも） |
| 404 | `RESOURCE_NOT_FOUND` | 口がない（`/admin/v2` の外、未定義のメソッド） |
| 409 | `SUBSCRIBER_ALREADY_EXISTS` | 登録で、同じ IMSI がすでにある |
| 409 | `SUBSCRIBER_ACTIVE` | `active` の加入者を消そうとした |
| 409 | `SUBSCRIBER_TERMINATED` | `terminated` の加入者を変更しようとした（PATCH） |
| 409 | `STATE_TRANSITION_NOT_ALLOWED` | `terminated` から `PUT …/state` で戻そうとした（`POST …/reinstate` を使う）、`terminated` でない加入者を `reinstate` しようとした |
| 500 | `SYSTEM_FAILURE` | Valkey の誤りなどの内部の誤り（詳細は返さず、ログの `ADMIN_ERROR`（ERROR）に出す）、ハンドラーのパニック（`SYS_PANIC`） |

- 400 で `invalidParams` が複数のときの `cause` は、必須の項目の欠落、必須の項目の不正、任意の項目の不正の順に優先する。
- 状態の規則（物理削除は `active` ではできない、`terminated` では変更できない、戻しは理由が必須）は aka-vecgen と同じ（設計概要 §6.2）。
- 同じ値への状態の変更は 200 で、監査ログに `unchanged` を残す（誤りにしない）。
- 口ごとの応答は OpenAPI が正。

### 6.3 監査ログが書けないとき

- 監査ログは Valkey の Stream と日ごとのファイルの両方に書く。どちらかに書けなくても、**操作は成功として扱い**、`AUDIT_WRITE_ERR`（ERROR。`to` が `stream` か `file`）を出す（操作そのものは終わっているため。aka-vecgen と同じ）。
- 前の日のファイルの圧縮と、持つ日数を過ぎたファイルの削除に失敗したら `AUDIT_MAINTAIN_ERR`（ERROR）を出し、1 時間後にまた試す。
- 起動のときにディレクトリに書けなければ起動しない（§3.2 の `AUDIT_DIR_ERR`）。

| 項目 | 値 |
|---|---|
| ヘッダーの読み込み | 10 秒 |
| 要求の読み込み・応答の書き出し | 30 秒 |
| 待っている接続 | 120 秒 |
| 本文の大きさ | 256 KiB |
| 停止のときに処理中の要求を待つ時間 | 10 秒 |

## 7. コマンド

| 状況 | 終了コード | 出力 |
|---|---|---|
| サブコマンドがない・不明・サーバーのサブコマンドに引数がある | 2 | 使い方を標準エラーに |
| 引数の誤り、対象の誤り | 1 | `error: …` を標準エラーに |
| 成功 | 0 | 結果を標準出力に |

| コマンド | 主な誤り |
|---|---|
| `client add` | `-trust-stamp` がない（必須）、同じ IP がある（`client update` を使う）、共有シークレットが 16〜128 文字の ASCII（空白と制御文字を除く）でない、`-secret-stdin` と `-generate` の両方 |
| `client update` / `remove` | その IP がない、変えるものがない |
| `sources check` | 登録簿が読めない（誤り）。証明書の期限切れと接続の失敗は数えて、1 つでもあれば終了コード 1（期限まで 30 日より近いのは警告だけ） |
| `admin-cert create` | `-hosts`・`-out` がない、`-days` が 1〜3650 の外、ファイルがある（`-force` で上書き）。鍵を先に書く（証明書だけが新しくなって組が合わなくなるのを避ける） |
| `fingerprint` | 標準入力に PEM の証明書がない |
| `healthcheck` | 同じコンテナの healthcheck の口に届かない、Valkey に届かない（compose の healthcheck が unhealthy にする） |

- 書き込みのコマンド（`client add / update / remove`、`admin-cert create`）は監査ログに残す（管理クライアント `cli`）。監査ログが書けなくても操作は成功とし、標準エラーに警告を出す。
- `admin-cert create` で Valkey に届かない（Valkey を起動する前に作るとき）は、監査ログを日ごとのファイルにだけ書く。
- `client` は Valkey に届かなければ誤り（終了コード 1）。

## 8. 耐障害性

### 8.1 時間の上限

| 対象 | 項目 | 値 | 備考 |
|---|---|---|---|
| auth → 取得先 | 要求 1 回 | 取得先ごとの `timeout`（既定 3 秒） | 接続・TLS・応答を含む。再試行しない |
| auth・acct | 要求の処理 | `RADIUS_REQUEST_TIMEOUT`（既定 4 秒） | 取得先のタイムアウトより長く、エッジの再送の間隔（5 秒）より短く |
| auth | EAP の会話（`eap:`） | 60 秒（更新のたびに延ばす） | 切れたら `EAP_CTX_NOT_FOUND` で拒否 |
| auth・acct | 重複応答のキャッシュ | 30 秒 | エッジの再送の窓（5 秒 × 2 回）より長く |
| すべて → Valkey | 接続・コマンド | 3 秒・2 秒 | |
| healthcheck の口 | Valkey の PING | 1 秒 | |
| auth・acct | 停止のときに処理中のパケットを待つ | 5 秒 | |
| acct | セッションの索引の掃除 1 回 | 1 分 | |

### 8.2 再試行

| 対象 | 再試行 | 備考 |
|---|---|---|
| auth → 取得先 | しない | 遮断器に任せる（契約の決定事項 10） |
| acct → Valkey | 3 回（100 ms〜1 秒） | それでも書けなければ応答しない（NAS の再送が再試行になる） |
| auth・admin・コマンド → Valkey | go-redis の既定（3 回、8〜512 ms） | |
| NAS（エッジ） | 5 秒で送り直す | 重複応答のキャッシュと Accounting の重複の判定で、数え直さない |

### 8.3 遮断器

取得先ごとに 1 つ持つ（`internal/auth/source`、`sony/gobreaker`。設計概要 §7.2）。本PoC は取得先の全体で 1 つだったので、外部の取得先の障害がほかの取得先の認証も止めた。

| 項目 | 値 |
|---|---|
| 開く条件 | 失敗（一時的な誤り・契約違反）が **5 回続く** |
| 失敗に数えないもの | 拒否（400・403・501）。加入者による正当な拒否で、取得先は動いている |
| 開いている間 | 要求を送らずに拒否する（`VECTOR_CIRCUIT_OPEN`） |
| 半開きにするまで | 開いてから **30 秒** |
| 半開きのとき | **3 件**まで通し、成功すれば閉じる。1 件でも失敗すればまた開く |
| 数え直し | 閉じている間に失敗の数を時間で区切らない（`Interval` 0。連続の数だけを見る） |
| 状態の変化のログ | `CB_OPEN`（WARN）・`CB_HALF_OPEN`・`CB_CLOSE`（INFO） |
| 状態の見え方 | 管理API の `/status`・`/sources` の `circuitBreaker`（auth の報告） |

- 本PoC から引き継いだ `Interval` 10 秒では、3 秒のタイムアウトが 10 秒の間に 5 回たまらず開かなかったので 0 にした（段階 2-2）。
- 取得先の登録簿を読み直すと、取得先のクライアントを作り直す（遮断器は閉じた状態から）。

## 9. 応答の対応

### 9.1 RADIUS

| 状況 | 応答 |
|---|---|
| 認証の成功 | Access-Accept（EAP-Success） |
| 認証の失敗（判定・取得先・検証・内部の誤り） | Access-Reject（EAP-Failure） |
| Challenge、永続 ID の要求 | Access-Challenge（EAP-Request） |
| RADIUS の層の誤り（共有シークレット、Message-Authenticator、EAP-Message がない）、上限を超えた、パニック | 応答しない |
| Accounting を記録した、または重複・順序の誤りとして扱った | Accounting-Response |
| Accounting を記録できない、RADIUS の層の誤り | 応答しない |

### 9.2 HTTP（管理API）

§6.2 の表のとおり。2xx は 200（読み出し・変更・状態）、201（登録）、204（削除）。

## 10. 作り方の決まり

- 誤りは `fmt.Errorf("…: %w", err)` で包み、`errors.Is`・`errors.AsType` で見分ける。パッケージの誤りの値は `ErrNotFound`・`ErrExists`・`ErrTransitionNotAllowed`・`ErrInvalid`（`internal/subscriber`）のように名前を付ける。
- 取得先の誤りは `*source.Error`（`Kind`・`SourceID`・`Status`・`Cause`・`Reason`・`LatencyMs`）にまとめ、分類（§4.4）でログと遮断器の扱いを決める。
- ログは呼び出しの一番外（ハンドラー、エンジン、processor）で 1 回だけ出し、下の層は誤りを返すだけにする。
- 内部の誤りの詳細（Valkey の誤りの文など）は管理API の応答に出さず、ログに出す。
- 共有シークレット、認証ベクター（RAND・AUTN・XRES・CK・IK）、鍵は、誤りの文にもログにも入れない。
